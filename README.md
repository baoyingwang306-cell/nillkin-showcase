# 📄 NILLKIN 悍能无畏 -  3D 交互展示页说明文档 

## 📌 项目概述

本项目是一个专为“NILLKIN 悍能无畏”键盘保护套打造的高级商业互动落地页。
页面采用了业界前沿的 **Scrollytelling（滚动叙事）** 技术，复刻了类似苹果官网的极简高级感。通过用户的上下滚动，精准控制 3D 渲染序列帧的播放、文字的视差浮现以及轮播图的滑动。

本版本（V2）针对移动端弱网环境和海量图片加载瓶颈，进行了底层渲染引擎的彻底重构，实现了“首屏秒开、滑动永不黑屏”的极致商业级体验。

---

## ✨ 核心技术黑科技 (Core Innovations)

1. **交错式骨架预加载 (Interlaced Skeleton Loading)：**
彻底废弃了“按顺序从头下到尾”的死板机制。网络请求分为三级优先级：
* *P0 级*：利用 HTML `<link rel="preload">` 头端预加载第 0 帧，实现首屏“秒亮”。
* *P1 级*：跳跃式抽取骨架帧（例如第 12、24、36 帧...），快速铺满整个滚动轴。
* *P2 级*：用户浏览时，后台静默填补剩余的细节帧。


2. **智能就近帧补偿算法 (Nearest-Frame Degradation)：**
当用户快速滑动到某个尚未下载完毕的区域时，引擎会以极低的算力成本，瞬间在内存中向前后寻找“最近的一张已下载骨架图”进行顶替渲染。**在用户视觉中，动画可能会有短暂的降帧，但绝对不会出现黑屏或闪烁。**
3. **双端动态帧率映射 (Dual-End Framerate Mapping)：**
* 桌面端（宽带+强算力）：加载完整的 **750 帧**高清序列，享受 60fps 满血丝滑。
* 移动端（4G+弱算力）：物理剥离一半素材，仅加载 **375 帧**优化版序列，同时保持手势滑动的 0-100% 进度完美对齐，大幅节省带宽。


4. **纯内存性能调优：**
DOM 节点（文字区块）的尺寸与绝对位置在初始化时一次性缓存；结合 DPR（设备像素比）动态放大 Canvas 画布，确保 Retina 屏幕绝对高清且不触发“布局抖动 (Layout Thrashing)”。

    │
    └── mobile/              # 📱 移动端专用资源库
        ├── H-d-2.webp       # 移动端首屏竖版静态图
        └── a000.webp ~ a374.webp # 👉 【移动端】抽帧优化版竖版序列帧 (共 375 张，注意无下划线)

### 💡 后期导出与压缩标准：

* 强烈建议使用 Python 脚本或自动化工具批量转换为 **`.webp`** 格式。

## ⚙️ 核心参数配置指南

如果后续 3D 动画帧数发生变化，只需修改 `index.html` 底部 `<script>` 标签开头的核心变量：

```javascript
// 1. 自动识别是否为移动端
const isMobile = window.innerWidth <= 768; 

// 2. 核心帧率控制 (桌面端 749，移动端抽帧至 374)
const startFrame = 0;
const endFrame = isMobile ? 374 : 749; 
const totalFrames = endFrame - startFrame + 1;

// 3. 滚动阻尼感 (缓冲顺滑度)
// 数值越小(如0.05)越平滑但有延迟感；数值越大(如0.5)越生硬但跟手。默认最佳体验为 0.12。
const easeAmount = 0.12; 

// 4. 骨架抽帧步长 (Skeleton Step)
// 决定了优先加载的间隔。移动端总帧数少，建议隔 12 帧抽一张；桌面端建议隔 24 帧。
const skeletonStep = isMobile ? 12 : 24; 

```

## 🚀 部署与运维排障指南

1. **缓存幽灵（调试必看）：**
移动端浏览器缓存极具攻击性。在更新了图片序列或修改了 JS 逻辑后，测试人员必须使用手机浏览器的“无痕/隐私模式”访问，否则极易出现新旧图片交替闪烁的报错。
2. **大文件传输：**
本项目双端图片总数超 1100 张，严禁在 GitHub / Gitee 网页端直接拖拽上传（会卡死且容易丢失文件）。请务必使用 **Git 命令行**或 **GitHub Desktop** 客户端进行 `Commit` 和 `Push`。
3. **商业级网络提速（终极建议）：**
虽然代码层面已经把预加载做到了极致，但物理链路的延迟无法靠代码消除。对于正式面向消费者的推广活动，建议将 `assets` 文件夹完整挂载至国内的 **阿里云 OSS / 腾讯云 COS**，并配置 CDN 加速，替换掉 GitHub 原始的相对路径，即可实现全网用户无死角秒开。
