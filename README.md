

# 📄 NILLKIN 悍能无畏 -  3D 序列帧交互展示页 SOP 

## 一、 项目概述

本项目旨在将高规格的 3D 渲染（如 C4D + Octane 输出的高清视觉序列）无缝转化为网页端的沉浸式交互体验。页面采用前沿的 **Scrollytelling（滚动叙事）** 架构，利用原生 HTML5 Canvas 高频重绘技术，通过用户的滚轮/手势精准驱动 3D 动画与视差文字的播放。

本版本（V3 终极版）着重重构了底层的“加载队列”与“渲染引擎”，彻底解决了移动端弱网环境下的首屏白屏、滑动卡顿及高刷屏发热等商业落地痛点。

## 二、 核心加载与渲染黑科技 (Core Engine Innovations)

在 V3 引擎中，我们摒弃了传统的“从头到尾线性加载”方案，自研并集成了以下 5 大极限性能优化机制：

1. **交错式骨架预加载 (Interlaced Skeleton Loading)：**
网络请求队列被重构为三级优先级（P0/P1/P2）。
* **P0 级：** 利用 HTML `<link rel="preload">` 头端标签，在解析代码前强制秒拉第 0 帧。
* **P1 级：** 引擎以间隔 10 帧（移动端）或 20 帧（桌面端）的步长，优先跳跃式下载“骨架帧”，瞬间铺满整条滚动时间轴。
* **P2 级：** 用户开始浏览后，后台每 40ms 高频并发请求，悄悄填缝补齐剩余细节帧。


2. **智能就近补偿防黑屏算法 (Smart Frame DegradationFallback)：**
当用户暴滑屏幕、触及尚未下载完成的帧时，`getNearestLoadedImage` 算法会以极低的内存开销，瞬间向前后寻找最近的已下载“骨架图”进行降级顶替。在视觉上仅表现为微小的掉帧，彻底杜绝画面黑屏或卡死。
3. **零消耗静止休眠机制 (Zero-Cost Idle Sleep)：**
加入了极高精度的差异阈值判定（`Math.abs(currentProgress - smoothedProgress) > 0.0001`）。当用户手指离开屏幕且动画缓冲结束时，Canvas 渲染引擎立刻进入 0 消耗休眠状态，停止重绘，大幅降低手机端发热与电池消耗。
4. **硬件级解码防卡顿 (Hardware Decoding API)：**
在拉取图片的瞬间，强制调用 `img.decode().then()` 原生异步解码 API。将图片的解码压力从浏览器主线程剥离交由 GPU 处理，保证了预加载过程绝不阻塞页面的正常滑动。
5. **双端独立帧率自适应 (Dual-End Framerate Adaptation)：**
引擎初始化时自动嗅探设备。桌面端加载全量 750 帧（60fps 满血顺滑）；移动端自动切换为 375 帧序列（抽帧减负），在保证 0-100% 滚动节点完美对齐的前提下，将整体网络负载砍半。

## 三、 素材预处理与压缩规范 (Asset Pipeline)

3D 序列帧的体积直接决定了网页的生命线，需严格遵循以下自动化压缩标准：

* **格式强制替换：** 严禁在网页中直接挂载原生的 `.png` 或 `.jpg` 序列。所有图片必须使用 Python 脚本批量转换为高压缩比的 **`.webp`** 格式。
* **物理降维打击：**
* **桌面端（`assets/`）：** 维持 16:9 横屏，单张体积控制在 80KB-120KB。
* **移动端（`assets/mobile/`）：** 使用 LANCZOS 高质量重采样算法，将物理宽度强制缩放至 `720px`，单张体积压榨至 **20KB-40KB**。


* **命名规范：** 使用连续无断档的三位补零数字命名（如 `a000.webp`、`a001.webp`），且严禁携带特殊符号或下划线，以完美契合 JS 的字符串拼接逻辑。
* **独立静态图压缩：** 底部轮播图等非序列静态素材，需独立执行压缩脚本，保留原有前缀名（如 `mode1.webp`）。

## 四、 页面结构与视图适配 (View & Layout)

* **视差文字图层：** 采用 `position: sticky` 将背景 Canvas 死死钉在视口，上层覆盖多个 `100vh` 高度的透明滚动容器。文字块进入视口 20%~80% 区域时，利用数学映射动态解算 `opacity` 和 `filter: blur()`，实现带景深感的高级淡入淡出。
* **DPR 视网膜适配：** 通过获取物理像素比（`window.devicePixelRatio`），动态放大 Canvas 的内部绘制尺寸并利用 CSS 缩回，解决高分屏下的图片发虚发糊问题。

## 五、 部署上线建议 (Deployment)

* **版本控制发布：** 面对海量零碎文件（约 1100 张图片），废弃浏览器拖拽上传，采用 Git 命令行或 GitHub Desktop 客户端进行跨国推送。
* **商业级分发加速：** 针对 NILLKIN 等商业曝光需求，正式上线时务必将 `assets` 资源包整体剥离，迁移托管至国内的 **阿里云 OSS** 或 **腾讯云 COS**，并配置 CDN 节点加速，将跨国请求延迟从 200ms+ 降维至 10ms 以内，真正实现全网秒开。
